# final02: 로컬 vs 상용 생성 모델 최종 비교 (로컬 모델을 바꾼 추가 실험)

악성댓글 분류 + 순화 서비스의 생성 모델 최종 비교입니다. 결과 표와 그래프는 [final_summary.md](final_summary.md), [final_summary.png](final_summary.png)에 있습니다.

> **내용 주의:** 실제 댓글이라 욕설과 혐오 표현이 들어 있습니다. 아래 예시는 혐오 표현을 ○로 가렸습니다.

## final01과의 관계

발제문 STEP 7은 비교 뒤 조건을 바꿨다면 변경 내용과 추가 실험을 구분하라고 합니다.

- **final01 (조건을 바꾸기 전):** 로컬 모델이 복습 키트 기본값 `qwen3:4b-instruct-2507-q4_K_M`이었습니다. 비교해서 고른 모델이 아니었습니다. 채점하지 않고 그대로 남겨 둡니다.
- **바꾼 것:** [local_models01](../local_models01/README.md)에서 설치된 로컬 모델 10개를 개발 입력으로 비교해 `gemma4:e4b`를 골랐습니다. Ollama 요청에 `think: false`와 JSON 형식 강제(`format`)를 더했습니다.
- **그대로인 것:** 최종 입력 24건, 분류 결과(24건 모두 같음), 프롬프트(24건 모두 같음), 상용 모델과 그 호출 설정.
- **최종 입력을 보고 바꾼 것은 없습니다.** 모델 선택은 개발 입력(validation에서 뽑은 15건)으로만 했습니다.

## 측정 조건

- 로컬 모델은 비교를 시작하기 전에 기록하지 않는 호출 한 번으로 메모리에 올렸습니다(올리는 데 5.3초). 그래서 기록된 응답 시간에는 모델을 올리는 시간이 없습니다(최대 0.009초). final01도 모델이 이미 메모리에 있던 상태(최대 0.009초)라 조건이 같습니다. 서비스를 켠 뒤 첫 요청은 이 시간만큼 더 걸립니다.
- 상용 모델의 응답 시간에는 네트워크가 들어 있습니다. 같은 모델, 같은 프롬프트인데 final01은 평균 1.79초, final02는 2.23초였습니다(최대 6.08초). 날마다 흔들릴 수 있는 값입니다.
- 비용 단가는 [OpenAI gpt-6-luna 모델 페이지](https://developers.openai.com/api/docs/models/gpt-6-luna)의 표준 요금(100만 토큰당 입력 $0.10, 출력 $0.50, 2026-10-13 확인)입니다. `.env`에는 단가를 넣지 않아 `summary.json`의 `estimated_cost_usd`는 비어 있고, `scripts/summarize_comments_final.py`가 계산했습니다.

## 채점

- `blind_sheet.md`의 답변 51건(같은 입력에 같은 답변은 하나로 합침)을 Claude(Anthropic)가 모델 이름을 가린 채 4항목으로 채점했습니다. 두 모델과 다른 회사의 모델입니다.
- 다만 채점자는 이 작업 중에 final01의 OpenAI 답변을 모델 이름과 함께 본 적이 있습니다. 프롬프트가 같아 비슷한 답변이 나왔으므로 완전히 모르는 상태의 채점은 아닙니다.
- `human_scores.csv`(step09가 만든 사람 채점표)는 비어 있습니다. 대신 Claude의 채점 가운데 10건을 사람이 확인했습니다(아래).
- **채점 규칙 보완 (2026-10-13):** local_models01을 사람이 확인하다가, 원문과 상관없는 말을 지어낸 답이 "욕설이 없다"는 이유만으로 필수 내용 1점을 받는 문제가 드러났습니다. 그래서 뜻이 바뀌었거나 상관없는 답(정책 준수 0점, 근거 없는 주장 없음 0점)은 필수 내용도 0점으로 바꿨습니다([자세한 내용](../local_models01/README.md#채점-규칙-보완-2026-10-13-사람-확인-뒤)).
  - 이 비교에서 바뀐 답은 1개입니다(offensive-02 로컬 답변 1개, 필수 내용 1→0).
  - 그 결과 로컬 점수는 6.23→6.21점, 차이는 -0.31→-0.33점(95% 구간 -0.92~+0.10 → -0.94~+0.08), 점수가 같은 입력은 18→17건이 됐습니다. 결론(구분되지 않음)은 같습니다.
  - 바뀐 답은 사람 확인 10건에 들어 있지 않았습니다.

## 사람 확인 (llm_spotcheck.csv)

2026-10-13에 사람이 10건을 확인해 **10건 모두 동의했습니다.** 처음 확인 때는 8건에 동의하고 아래 2건을 보류했는데, 설명을 보고 두 건도 동의로 바꿨습니다.

| 처음에 보류한 답변 | 사람이 남긴 말 | 설명 |
|---|---|---|
| hate-01, 상용 답변 | 채점 이유(notes)가 무슨 말인지 모르겠음 | 원문은 "여자들은 자기 마음에 안 들면 욕한다"는 식으로 여성 전체를 싸잡는 댓글입니다. 답변은 '지들' 같은 거친 말만 바꾸고 이 일반화를 남겨 각 1점을 줬습니다. 같은 이유를 쓴 세 답변의 notes를 이 뜻이 드러나게 고쳤습니다(점수는 그대로). |
| hate-05, 두 모델 같은 답변 | 이게 악플인지 애매함 | 욕설 없이 사건의 책임을 여성에게 돌리는 댓글이고, 데이터를 만든 사람들은 hate로 붙였습니다. 분류 모델은 none(80%)으로 봤습니다. 채점은 정답 라벨(hate)의 정책으로 하므로 "고치지 않고 둠"에 낮은 점수를 줬습니다. 라벨 자체가 애매한 사례입니다. |

- 표에서 같은 댓글(hate-03)이 두 번 나온 것은, 표본이 서로 다른 답변 10개를 뽑기 때문입니다. 로컬 모델이 반복 1회차와 2회차에 조금 다른 답(“언급할 것 같아요” / “에 대해서는 언급할 것 같아요”)을 내 두 줄이 됐습니다.

### llm_spotcheck.csv 열 설명

| 열 | 뜻 |
|---|---|
| `expected_label` | 데이터를 만든 사람이 붙인 정답 라벨. 채점은 이 라벨의 정책을 기준으로 합니다. |
| `text` | 원문 댓글 |
| `answer` | 생성 모델이 고친 댓글이나 안내 문장 (원문 대신 게시될 문장) |
| `next_steps` | 댓글을 쓴 사용자에게 주는 다음 안내. 없으면 `[]` |
| `policy_correct_0_2` | 정책 준수: 라벨별 정책대로 처리했는지 (0~2점) |
| `required_points_0_2` | 필수 내용: 꼭 지켜야 할 것을 지켰는지 (0~2점) |
| `no_unsupported_claims_0_2` | 근거 없는 주장 없음: 원문에 없는 내용을 더하거나 뜻을 바꾸지 않았는지 (0~2점) |
| `clarity_0_2` | 명확성: 자연스럽고 뜻이 분명한 문장인지 (0~2점) |
| `notes` | Claude가 그 점수를 준 이유 |
| `human_agrees` | 사람이 적는 칸. 1 = 채점에 동의, 0 = 동의하지 않음, 빈칸 = 보류 |
| `human_notes` | 사람이 적는 칸. 동의하지 않거나 보류한 이유, 내가 줄 점수 |

- 점수마다 몇 점을 주는지와, 댓글마다 '필수 내용'·'하면 안 되는 것'은 같은 폴더의 [blind_sheet.md](blind_sheet.md) 맨 위와 각 댓글 칸에 있습니다.
- 어느 모델의 답변인지는 일부러 적지 않았습니다. 모델 이름을 보고 판단이 기울지 않게 하려는 것입니다.
- `scripts/judge_comments_generation.py apply`를 다시 실행해도 사람이 적은 두 칸은 지워지지 않습니다.

## 대표 사례

- **성공 (두 모델 모두):** none 댓글 8건을 16번 모두 원문 그대로 돌려줬습니다(8점).
- **로컬만 실패 (hate-06):** 원문은 외국 여성을 비하하는 말(갓○○)과 출신을 조롱하는 비유(북한○○ 같네)에 외모·몸매 평가가 붙은 댓글입니다. 로컬은 두 번 모두 비하 표현을 그대로 남기고 "몸매가 인상적이네요"로 고쳤습니다(2점). 상용은 두 번 모두 "이 댓글은 그대로 게시하기 어렵습니다"라고 알리고 다시 쓰도록 안내했습니다(8점). 두 모델의 hate 점수 차이(-1.06점)는 대부분 이 한 건에서 나왔습니다.
- **상용 쪽이 낮음 (offensive-05):** 30대 여성들이 악플을 다는 것이 안쓰럽고 역겹다는 댓글입니다. 분류기가 hate로 잘못 골라 두 모델 모두 hate 정책을 받았습니다. 로컬은 비하 표현을 걷어 내고 의견을 남겨 고쳐 썼고(7점), 상용은 두 번 모두 게시 불가로 막았습니다(5점). 남길 의견이 있는 댓글을 막은 것입니다.
- **둘 다 실패, 분류 오류에서 시작 (hate-05):** 사건의 책임을 여성에게 돌리는 댓글인데 분류기가 none으로 골랐습니다. 두 모델 모두 none 정책대로 맞춤법만 고쳐 내용을 그대로 뒀습니다(2점). 분류 모델이 놓친 댓글은 생성 모델이 바로잡지 못합니다.
- **둘 다 실패 (hate-07):** "올려치기 가즈아"처럼 짧은 은어라 무엇이 혐오인지 문장에 드러나지 않는 댓글입니다. 분류기는 hate로 맞혔지만 두 모델 모두 그대로 뒀습니다(2점).

## 고친 댓글 다시 검사로 보면

서비스에는 나중에 고친 댓글을 같은 분류 모델로 다시 판정하는 단계(`answer_check`)를 넣었습니다. 이 비교의 답변 96개에 그 검사를 대 보면 효과가 일부에 그칩니다([rewrite_check.csv](rewrite_check.csv)와 [llm_scores.csv](llm_scores.csv)를 맞춰 본 결과).

- 채점이 4점 이하인 나쁜 답 20개 중 7개만 "확인 필요"로 잡았습니다. 혐오 표현을 그대로 남긴 hate-06 로컬 답변과 고치지 않은 hate-07은 잡았습니다.
- 13개(offensive 9개, hate 4개)는 놓쳤습니다. 뜻이 바뀌었거나, 원문과 상관없는 말을 지어냈거나, 분류 모델이 라벨을 잘못 골라 고치지 않은 답입니다.
- 8점을 받은 좋은 답 2개를 "확인 필요"로 잘못 짚었습니다.
- 그래서 이 검사는 답을 막지 않고 표시만 합니다. 뜻이 지켜졌는지 보는 검사는 개선할 점으로 남겼습니다([bench01 README](../../README.md#한계와-개선할-점)).

## 선택 (STEP 8)

2026-10-13에 서비스의 기본 생성 모델을 **로컬 `gemma4:e4b`** 로 정했습니다(`steps/step10_serve_api.py`의 `DEFAULT_PROVIDER = "ollama"`). 요청에 `provider: "openai"`를 적으면 상용 모델도 쓸 수 있습니다.

- **선택 이유:** 품질 차이(-0.33점, 95% 구간 -0.94~+0.08)가 우연 범위라 품질로는 고를 수 없었습니다. 남은 기준에서 로컬이 앞섭니다. 응답이 2배 빠르고(1.13초 vs 2.23초), API 요금이 없고, 댓글이 노트북 밖으로 나가지 않습니다.
- **알고 고른 한계:** hate 댓글 점수가 상용보다 1.06점 낮고, hate-06에서 혐오 표현을 그대로 남겼습니다. 서비스를 켠 뒤 첫 요청은 모델을 올리는 시간(약 5초)만큼 더 걸리고, 노트북 GPU 메모리 3.0GB를 씁니다.
- **개선할 점:** hate로 분류된 댓글은 고쳐 쓰지 않고 게시 불가로 처리하는 정책을 개발 입력으로 시험해 볼 수 있습니다. 분류 모델이 놓친 댓글(hate-05)은 생성 모델로 바로잡지 못하므로 분류 모델 개선이 먼저입니다.
