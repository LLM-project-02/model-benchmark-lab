# 시연 영상 대본 (찍는 시간 약 1분 40초, 편집 후 약 1분 25초)

악성댓글 분류 + 순화 서비스의 검수 콘솔을 찍는 대본입니다. 장면 2~5의 댓글은 2026-10-14에 서버로 5번 이상 보내 매번 같은 권장 조치가 나온 것만 골랐습니다.

- 발표 슬라이드([bench01_comments_slides_심플_피드백반영.pptx](bench01_comments_slides_심플_피드백반영.pptx))의 8번째 장에 넣습니다. 발표자 노트는 영상을 약 70초로 잡았고(장면 6의 기다림을 잘라 내면 됩니다), 노트 기준 발표 전체는 약 4분 45초입니다.

- 화면에 나오는 댓글은 모두 직접 만든 예시입니다. 실제 댓글과 실명은 없습니다.
- 혐오 표현 예시가 나오므로, 영상 첫 화면에 "예시에 혐오 표현이 나옵니다" 자막을 넣습니다.

## 찍기 전 준비 (영상에 넣지 않음)

1. 켜 둔 서버가 있으면 두 터미널 모두 Ctrl+C로 끕니다. 새 코드(사람 검토 규칙)는 다시 켜야 적용됩니다.
2. 터미널 1 (저장소 폴더): `uv run python steps/step10_serve_api.py`
3. 터미널 2 (저장소 폴더): `uv run --group ui streamlit run scripts/comments_streamlit_app.py`
4. 브라우저에서 `http://127.0.0.1:8501`이 열립니다. 창을 최대화하고, 확대는 100%로 두고, 다른 탭과 알림(Windows 방해 금지)을 끕니다.
5. 왼쪽 메뉴가 "연결됨", 생성 모델이 "로컬"인지 봅니다.
6. **준비 요청:** `이걸 기사라고 썼냐? 기자 수준 진짜 한심하다.`를 한 번 검수합니다. 처음에는 두 모델(생성, 뜻 검사)을 GPU에 올리느라 12초쯤 걸립니다. 끝나면 F5로 새로 고침해 화면을 비웁니다.
7. [demo_comments.csv](demo_comments.csv)를 바탕 화면처럼 찾기 쉬운 곳에 복사해 둡니다.
8. **녹화:** Win+Shift+R(캡처 도구 녹화)로 브라우저 창 영역을 고르고 시작합니다. 파일 선택 창도 함께 찍힙니다. 끝나면 캡처 도구 창에서 저장합니다.

## 결과가 대본과 다를 때

- **고친 문장은 달라도 됩니다.** 생성 모델은 매번 조금 다른 문장을 씁니다. 확인할 때도 문장은 달랐고 권장 조치는 같았습니다.
- **권장 조치가 다르면 같은 댓글로 한 번 더 검수합니다.** 장면 2~5의 댓글은 확인할 때 5번 이상 모두 같은 권장 조치였습니다.
- **장면 6의 숫자는 한 건쯤 다를 수 있습니다.** 9번 중 6번이 위 숫자였고, 나머지는 순화 후 게시와 사람 검토가 한 건씩 바뀌었습니다. 다르게 나와도 그대로 써도 됩니다.
- **많이 느리면:** 다른 터미널에서 `ollama ps`를 실행해 두 모델(gemma4:e4b, qwen3:4b-instruct)이 모두 "100% GPU"인지 봅니다. 아니면 GPU를 쓰는 다른 프로그램을 닫고 준비 요청부터 다시 합니다. 뜻 검사를 넣은 뒤 GPU 메모리 여유가 400~500MB뿐이기 때문입니다.
