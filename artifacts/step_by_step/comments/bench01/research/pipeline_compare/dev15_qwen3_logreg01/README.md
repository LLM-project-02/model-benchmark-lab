# dev15_qwen3_logreg01: 세 경로 비교 (로지스틱 회귀 + LLM 추가 실행, 예비 결과)

[dev15_qwen3_01](../dev15_qwen3_01/README.md)에서 모델이 없어 실행하지 못한 로지스틱 회귀 + LLM 경로만, 같은 개발 예제 15개로 실행했습니다.
LLM 단독·KcELECTRA + LLM은 다시 실행하지 않고 dev15_qwen3_01의 결과와 사람 평가를 재사용해 세 경로를 비교합니다.

> **예비 결과:** 개발 예제 15개(품질 비교는 14개)를 평가자 1명이 평가했습니다. 경로 사이의 차이는 통계적으로 확인되지 않았습니다(아래).
>
> **이 실험이 비교한 것:** 같은 공통 파이프라인 안에서 분류 경로만 바꾼 비교입니다. 공통 파이프라인 도입 전후를 비교한 실험이 아니라서,
> 공통 파이프라인 도입 자체의 효과에 대해서는 말할 수 없습니다.

## 대표 실패 사례

표의 P·M·N은 사람 평가(정책 준수·의미 보존·새 사실 추가)입니다. 라벨은 "참고 라벨 / 경로의 판정"입니다.

**1. 분류기가 문제 댓글을 none으로 판정해 원문을 그대로 돌려줌 (offensive-01, 같은 양상: hate-01·hate-03)**

원문: "한혜진 진짜 지루해서 채널 돌렸다 하차해라" (참고 라벨 offensive)

| 경로 | 판정 | 생성 답변 | P / M / N | 평가 메모 |
|---|---|---|---|---|
| LLM 단독 | offensive | 한혜진 채널을 지루해서 끊었어요. | yes / no / yes | 채널 돌렸다는 관용어구가 해당 인물의 채널로 바뀜 |
| 로지스틱 회귀 | none (0.43) | 원문 그대로 | no / yes / no | |
| KcELECTRA | offensive (0.72) | 한혜진 채널이 지루해서 하차하려고 합니다 | yes / no / yes | (위와 같음) |

로지스틱 회귀가 none으로 판정해 그대로 돌려준 문제 댓글은 3개(offensive-01, hate-01, hate-03)이고, 3개 모두 의미 보존 yes·정책 준수 no였습니다.

**2. offensive 댓글을 hate로 판정해 원문을 두고 다시 쓰라는 안내만 붙임 (offensive-03)**

원문: "돼지같은 것들은...다 이유가 있다~*" (참고 라벨 offensive)

| 경로 | 판정 | 생성 답변 | P / M / N | 평가 메모 |
|---|---|---|---|---|
| LLM 단독 | offensive | 돼지같은 것들은...다른 이유가 있을 수 있습니다~ | no / no / yes | 돼지같다는 것 자체가 비하적인 목적이 강함 |
| 로지스틱 회귀 | hate (0.54) | 원문 그대로 + "차별이나 혐오를 담지 않도록 수정해 보세요" 안내 | no / yes / no | |
| KcELECTRA | hate (0.92) | 원문 그대로 + 같은 취지의 안내 | no / yes / no | |

이 예제에는 두 가지 실패가 함께 있습니다.

- **분류 오류:** offensive 댓글을 hate로 잘못 판정했습니다.
- **생성의 정책 미준수:** 판정된 hate 정책은 혐오 표현을 지우고 남는 의견만 쓰거나, 남길 의견이 없으면 게시하기 어렵다고 알리는 것입니다.
  그런데 두 분류기 경로 모두 비하 표현이 든 원문을 answer에 그대로 돌려줬습니다.
  라벨이 맞았더라도(offensive 정책: 불쾌한 표현을 걷어 내고 정중하게 바꿈) 원문 그대로는 정책 위반입니다.

| LLM 단독 | offensive | 원문의 '○○들'을 남긴 채 문장만 다듬음 | no / yes / no | 원래 의견은 유지했으나 공격적인 어조가 충분히 완화되지 않음 |
| 로지스틱 회귀 | offensive (0.35) | 아무리 재미있고 잘나가던 프로라도 ○○들이 참여하는 순간은 자연스럽지 않은 웃음으로 바뀌기 쉽습니다. 이 점을 명심해 주세요. | no / yes / no | 원문에도 '명심해라'가 있어 '명심해 주세요'는 새로운 정보가 아님 (정정: 새 사실 추가 yes→no) |
| KcELECTRA | hate (0.92) | 원문 그대로 + 표현을 바꾸라는 안내 | no / yes / no | (LLM 단독과 같은 메모) |

- KcELECTRA는 라벨을 맞혔지만 생성 단계에서 hate 정책을 따르지 않았습니다(생성의 정책 미준수).
- 로지스틱 회귀는 hate를 offensive로 잘못 판정했습니다(분류 오류). 그런데 offensive 정책으로도 불쾌한 표현을 걷어 내야 하는데,
  '○○들'을 남겼습니다. 그래서 생성의 정책 미준수에도 해당합니다.

**4. 세 경로 모두 원문의 뜻을 바꿈 (offensive-04)**

원문: "위너인줄.. 진짜 기자 기사좀 똑바로 쓰지..근데저런 인성이 안좋은 일반인 결혼 기사도 써주나???" (참고 라벨 offensive, 세 경로 판정 모두 offensive)

| 경로 | 생성 답변 (앞부분) | P / M / N |
|---|---|---|
| LLM 단독 | …그런 인성의 일반인 결혼 기사도 함께 써 주실 수 있나요? | yes / no / yes |
| 로지스틱 회귀 | …그런 인성의 일반인 결혼 기사도 함께 써주실 수 있나요? | yes / no / no |
| KcELECTRA | …그런 인성에 대한 기사도 함께 보여주실 수 있나요? | yes / no / yes |

- 평가 메모는 세 경로 모두 "인성이 안좋은 일반인의 기사를 써달라는 댓글이 아님. 판단오류"입니다.
- 기자를 비꼬는 질문을 기사를 써 달라는 요청으로 바꿨습니다.
- 판정이 같아도 같은 LLM이 같은 방식으로 문맥을 잘못 읽었습니다.

**5. 취지가 바뀐 재작성 (hate-04, 로지스틱 회귀)**

원문: "○○들원래 부러우면 이렇게댓글다는거냐?ㅋㅋ" (참고 라벨 hate)

| 경로 | 판정 | 생성 답변 | P / M / N | 평가 메모 |
|---|---|---|---|---|
| 로지스틱 회귀 | offensive (0.38) | 여러분이 부러워할 만한 점이 있다면 그걸 공유해 주시면 좋겠습니다. | no / no / no | 비꼬는 질문이 정보 공유 요청으로 바뀌어 원문의 취지가 달라짐 |

LLM 단독(offensive)과 KcELECTRA(hate)는 이 예제에서 정책 준수·의미 보존 모두 yes였습니다.

이 밖에 LLM 단독의 미완료(hate-02)와, 문제없는 댓글을 고친 사례(none-02·04·05)는 [dev15_qwen3_01 README](../dev15_qwen3_01/README.md#대표-실패-사례)에 있습니다.

## 확인된 점과 한계

- **이 표본에서 확인된 것:**
  - 세 경로 모두 실행 오류는 없었습니다. 미완료는 LLM 단독 1건입니다.
  - 정책 준수는 KcELECTRA + LLM이 10/14로 가장 높았고, 로지스틱 회귀 + LLM과 LLM 단독은 6/14로 같았습니다.
  - 로지스틱 회귀 + LLM은 새 사실 추가가 없었고(0/14, 정정 반영), 의미 보존이 가장 높았습니다(10/12).
    다만 문제 댓글을 그대로 돌려준 답변이 4개이고 hate 정책 준수가 0/4였습니다. 고치지 않고 돌려준 결과가 섞인 값입니다.
  - 정책 준수 no의 원인은 분류 오류와 생성의 정책 미준수이고, **둘이 한 답변에서 함께 일어날 수 있습니다.**
    - 분류 오류만: 문제 댓글을 none으로 판정하고 none 정책대로 원문을 둔 경우 (로지스틱 회귀 offensive-01·hate-01·hate-03)
    - 생성 미준수만: 라벨은 맞았는데 정책을 따르지 않은 경우 (KcELECTRA hate-05)
    - 둘 다: offensive를 hate로 잘못 판정하고, 비하 표현을 그대로 돌려준 경우 (로지스틱 회귀·KcELECTRA offensive-03).
      hate를 offensive로 잘못 판정하고 혐오 표현을 남긴 경우 (로지스틱 회귀 hate-05)
    - 위 구분은 판정 라벨과 정책 문장을 기준으로 한 사례 설명이고, 사람 평가 항목은 아닙니다.
- **한계:**
  - 개발 예제 15개(품질 비교 14개), 평가자 1명입니다. 평가 기준 설명서, 두 번째 평가자, 평가자 간 일치도가 없습니다.
  - 경로 이름을 가리고 평가했는지는 기록되지 않았습니다.
  - 경로 쌍별 차이는 통계적으로 확인되지 않았습니다(정확 McNemar p ≥ 0.125).
  - 경로당 1회 실행이라 반복 실행에 따른 변동을 재지 않았습니다. 로지스틱 회귀 경로는 다른 시각에 실행했습니다.
  - LLM은 qwen3 4B 하나입니다. 서비스 기본 모델 `gemma4:e4b`나 상용 모델에서도 같은 경향인지는 모릅니다.
  - LLM 단독은 프롬프트 구성도 다르므로(라벨까지 고름), 경로 차이를 분류기만의 효과로 볼 수 없습니다.
  - 공통 파이프라인 도입 전후 비교가 아니므로, 공통 파이프라인 도입 자체의 효과는 이 실험으로 말할 수 없습니다.
  - 최종 평가용 데이터(test, `generation_eval.jsonl`)로는 실행하지 않았습니다.
