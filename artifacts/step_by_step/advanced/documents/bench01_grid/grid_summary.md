# 심화 데이터 추가 비교: 모델 크기 · 학습률 · 에포크

심화 문서 데이터(train 180건, validation 60건)에서 모델 크기, 학습률, 에포크가 분류 점수에 주는 영향을 본 추가 분석입니다.
**validation으로만 평가했고 test는 쓰지 않았습니다.** 최종 모델 선택과 test 결과(`../bench01/`)는 이 분석으로 바뀌지 않습니다.

- 폴더 이름: `bench01`은 실험한 사람(LEARNER), `grid`는 여러 설정을 격자처럼 조합해 돌렸다는 뜻입니다.
- 실험 1회당 한 줄인 원본 표: [grid_runs.csv](grid_runs.csv)
- 그래프: [grid_summary.png](grid_summary.png), [ep20_summary.png](ep20_summary.png)

## 설정

- 모델: klue/roberta-small, klue/roberta-base, klue/roberta-large (같은 계열)
- 고정: 입력 512토큰, 실질 배치 16, 최적화 설정은 step04 기본값
- 바꾼 것: 학습률 1e-5 · 2e-5 · 5e-5 · 1e-4, 시드 42 · 43 · 44, 에포크 10(일부 20)
- 비교 기준: 기준 모델 TF-IDF + 로지스틱 회귀 validation Macro F1 0.8157, 잠긴 최종 모델 `roberta_len512_ep6_lr5e5` 0.8471
- 점수는 validation Macro F1입니다. validation이 60건이라 1건이 약 1.7%p입니다.

## 결론

- **모델 크기:** 가장 좋은 학습률에서 small, base, large가 모두 0.85 근처로 1건 이내 차이입니다. large는 추론이 약 7배 느리고 GPU를 6.5GB 쓰지만 앞서지 않았습니다.
- **학습률:** 세 크기 모두 5e-5가 가장 좋았습니다. 1e-4에서는 small은 멀쩡하고, base는 시드에 따라 크게 흔들리고, large는 무너졌습니다.
- **에포크:** 3에포크는 부족하고 6~10에서 대부분 올라옵니다. 20까지 가면 세 크기 모두 0.85 근처에 머물고, large는 validation 손실이 커지며 과적합됩니다.
- **최종 모델:** 잠긴 모델(klue/roberta-base, 512토큰, 5e-5, 에포크 6)이 가장 좋은 영역에 있어 바꿀 이유가 없습니다.

## 한계

- 같은 설정에서도 시드에 따라 0.03~0.10이 흔들립니다. 가장 좋은 설정과 기준 모델의 차이(2~3건)가 이 흔들림과 비슷한 크기입니다.
- large와 에포크 20은 시드 하나의 결과입니다.
- 에포크 3·6·10 비교는 에포크 10으로 학습하면서 중간 시점 점수를 읽은 것입니다. 에포크 3으로 따로 학습한 결과와는 학습률 일정이 다릅니다.
- 학습 데이터 180건, validation 60건의 합성 데이터에서 본 결과입니다.

## 실행 방법

저장소 코드는 고치지 않고 `steps/step04_train_classifier.py`의 `run_training()`에 인자를 넘겨 실행했습니다.

```python
run_training(
    data_dir="data/advanced/documents",
    learner_dir="artifacts/step_by_step/advanced/documents/bench01_grid",
    run_name="base_lr5e5_s42",          # <크기>_lr<학습률>_[ep<에포크>_]s<시드>
    model_name="klue/roberta-base",
    learning_rate=5e-5, epochs=10, max_length=512, seed=42,
    batch_size=4, accumulation_steps=4,  # large는 8GB GPU에 맞춰 batch_size=2, accumulation_steps=8
    baseline_run="baseline",
)
```

- 심화 데이터는 한 묶음의 라벨이 서로 다르므로, `step02_check_data`를 불러오기 전에 `lesson_settings.DATA_LEVEL`을 `advanced`로 두어야 합니다.
- klue/roberta-small은 모델 설정에 `torchscript=true`가 있어 결과를 튜플로 돌려줍니다. step04가 `output.loss`를 쓰므로 불러올 때 `torchscript=False`를 넘겼습니다. 가중치와 구조는 같습니다.
- 실행에 쓴 보조 스크립트는 저장소에 넣지 않았습니다.
