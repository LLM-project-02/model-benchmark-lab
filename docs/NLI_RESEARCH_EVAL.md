# 보고서 세 경로 비교 — 사람 평가 기준 (2026-10-16)

보고서 검수의 세 경로(LLM 단독 / 로지스틱 회귀 + LLM / RoBERTa + LLM)가 같은 근거 문장·주장 한 쌍에 대해 낸
출력(판정 label, 설명 explanation, 수정안 suggestion)을 사람이 평가하는 기준이다. 자동 품질 점수는 만들지 않는다.

- 기록: `nli/run_research_compare.py`의 `results.csv`(평가 열 비어 있음) 또는 화면(파이프라인 비교 → 보고서)의 CSV 내보내기
- 평가 시트: `nli/build_research_eval_sheet.py <실행 이름>` → `eval_sheet.csv`(경로를 A·B·C로 가림) + `eval_key.csv`(경로·참고 라벨)
- 집계: `nli/summarize_research_eval.py <실행 이름>` (평가가 끝난 시트로 경로별 yes 비율과 참고 라벨 일치율)

## 평가자가 보는 것

한 행에 원문(있을 때 `source_text`), 근거 문장(`evidence`), 검증할 주장(`claim`), 출력 판정(`output_label`),
설명, 수정안이 함께 있다. 참고 라벨(정답)과 경로 이름은 시트에 없고 `eval_key.csv`에만 있다(평가가 끝난 뒤 합친다).

## 항목 (열 이름 · 값은 `yes` / `no` / 빈칸)

| 열 | 항목 | yes의 뜻 | 좋은 방향 |
|---|---|---|---|
| `eval_evidence_faithful` | 근거 충실성 | 설명·수정안의 사실 주장을 모두 근거 문장(과 주장)에서 확인할 수 있다 | yes |
| `eval_label_explanation_consistent` | 판정과 설명의 일치 | 설명이 그 행의 출력 판정과 같은 결론을 말한다 | yes |
| `eval_suggestion_valid` | 수정안 타당성 | 수정안(또는 null)이 출력 판정의 지시에 맞다 | yes |
| `eval_new_facts` | 새 사실 추가 | 설명·수정안에 근거·주장 어디에도 없는 사실을 더했다 | **no (yes가 문제)** |
| `eval_memo` | 메모 | 판단 근거, 애매한 점, `(판정 재검토 필요)` 표시 여부 등 | — |

### 1. 근거 충실성 (`eval_evidence_faithful`)

- **yes:** 설명과 수정안에 나온 숫자·날짜·주체·행위가 근거 문장에 있다. 주장에서 인용한 부분은 주장에 있는 그대로다.
- **no:** 근거에 없는 내용을 근거에 있다고 말한다. 근거를 잘못 인용한다(예: 근거의 "3억 원"을 "5억 원"이라고 씀).
- 판정이 맞는지는 이 항목에서 보지 않는다. 판정이 틀려도 설명이 근거를 정확히 인용했으면 yes다.
- 이전 LLM 비교(`nli/score_llms.py`)의 `근거충실성(0/1)`은 정의 문서가 없었다. 이 항목은 그 이름을 이어받아 위처럼 정의했다(yes = 1).

### 2. 판정과 설명의 일치 (`eval_label_explanation_consistent`)

- 기준이 되는 판정은 그 행의 `output_label`이다. LLM 단독은 LLM이 고른 라벨이고, 분류기 경로는 분류기 판정이다
  (분류기 경로에서 LLM이 다른 라벨을 적으면 형식 오류로 기록되어 평가 대상이 아니다).
- **yes:** 판정이 뒷받침함이면 설명이 근거가 주장을 뒷받침한다고 말하고, 확인 불가이면 근거에서 확인할 수 없다고 말하고,
  모순됨이면 근거와 다른 부분을 짚는다.
- **no:** 설명이 판정과 반대 결론을 말한다(예: 모순됨인데 "원문과 일치한다", 확인 불가인데 "원문과 다르다").
- 설명 끝에 `(판정 재검토 필요)`를 붙이고 판정과 다른 결론을 말했으면 **no**로 두고 메모에 "재검토 표시"라고 적는다.
  (서비스 규칙상 허용되는 표시지만, 이 항목은 출력 판정과 설명이 맞는지만 본다.)
- 판정이 참고 라벨과 같은지는 사람이 평가하지 않는다. 집계 스크립트가 `eval_key.csv`의 참고 라벨로 따로 계산한다.

### 3. 수정안 타당성 (`eval_suggestion_valid`)

서비스 지시(`nli/explainer.py` POLICIES)를 출력 판정에 맞춰 적용한다.

| 출력 판정 | yes | no |
|---|---|---|
| 모순됨 (contradiction) | 근거에 맞게 고친 보고서 문장. 근거와 일치하고, 주장의 나머지 부분은 유지하며, 새 사실이 없다 | 수정안 없음(null), 여전히 근거와 다름, 다른 내용으로 바꿈 |
| 확인 불가 (neutral) | 작성자에게 출처·근거 자료를 묻는 짧은 질문 한 문장 | 수정안 없음, 질문이 아닌 단정, 근거와 무관한 질문 |
| 뒷받침함 (entailment) | null (수정안 없음) | 수정안을 냄 |

### 4. 새 사실 추가 (`eval_new_facts`, yes = 문제)

- **yes:** 설명이나 수정안에 근거·주장 어디에도 없는 사실(숫자, 날짜, 주체, 원인, 결과, 일정 등)이 있다.
- **no:** 근거·주장에 있는 내용과 일반적인 연결 표현만 썼다.
- 1번(근거 충실성)과 겹칠 수 있다. 근거를 잘못 인용한 것은 1번 no, 근거에 없는 새 내용을 더한 것은 4번 yes로 둘 다 적는다.

## 빈칸과 분모

- 출력이 없는 행(오류·미완료·실행 안 함, 시트의 `eval_target`이 `no (...)`)은 **모든 평가 칸을 비워 둔다.**
  화면에서도 출력이 없는 경로의 평가 입력은 비활성이다.
- 판단할 수 없으면 빈칸으로 두고 메모에 이유를 적는다. 빈칸은 no로 세지 않는다.
- 비율의 분모는 그 항목에 yes/no가 적힌 건수다. 경로 사이 비교는 같은 example_id에서 비교하는 경로가 모두 출력을 낸 예제만 쓴다.

## 평가 절차

1. 실행 폴더에서 `eval_sheet.csv`를 복사해 평가본을 만든다(원본 시트는 두고, 평가본 이름은 `eval_sheet_<평가자>.csv`).
2. 경로 이름과 참고 라벨을 보지 않고 위 기준으로 채운다. 가능하면 평가자 2명이 따로 채운다.
3. `uv run python nli/summarize_research_eval.py <실행 이름> --eval-file eval_sheet_<평가자>.csv`로 집계한다.
4. 평가자 사이 불일치는 메모로 남기고, 합의본을 따로 만든다(원래 평가본은 고치지 않는다).

## 이전 기준과의 관계

| 이전 기준 | 위치 | 이번 기준 |
|---|---|---|
| 근거충실성(0/1) | `nli/score_llms.py` (LLM 비교 eval, 정의 문서 없음) | 1번으로 정의해 이어 씀 |
| 필수내용(0/1), 금지내용없음(0/1) | `nli/score_llms.py` + `cases.jsonl`의 required_points·forbidden_claims | 쓰지 않음. 근거·주장 쌍 데이터에는 행별 필수·금지 내용이 없다. 3번·4번이 같은 역할을 일부 맡는다 |
| 단정 표현·재검토 표시·수정안 위치 자동 확인 | `nli/compare_llms.py`, `stress_compare.py`, `compare_prompts.py` | 자동 확인은 이번 연구 기능에 넣지 않았다(필요하면 기록의 explanation·suggestion으로 따로 계산) |
