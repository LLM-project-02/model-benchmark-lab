# 모델 선정 기록 (분류 모델 · 생성 모델)

- 분류 모델 선정은 test 평가 전에 확정했고, 이후 설정을 바꾸지 않았다.
- test 이후의 실험은 '사후 분석'으로 구분하며, 공식 선정과 공식 test 결과를 바꾸지 않는다.
- 생성 모델(LLM) 선정과 이후 실험은 아래 '생성 모델(LLM) 선정' 섹션에 기록한다.

# 1. 분류 모델

## 최종 선정

- 분류기: klue/roberta-base (결과 폴더: roberta_lr2e5_ep6, 6 epoch 학습 중 best epoch 6)
- 확률 보정: temperature scaling, T = 2.77 (validation으로 결정)
- 비교용 베이스라인: TF-IDF + 로지스틱 회귀
- 이후 설정 변경 없이 test로 한 번만 평가한다

## 선정 규칙 (실험 전에 정함)

1. validation Macro-F1이 가장 높은 모델을 고른다.
2. 최고와의 차이가 0.005 이내인 모델들은 실력이 같다고 보고,
   B 절반 보정 후 loss가 가장 낮은 모델을 고른다.
3. B 절반: validation을 원문 묶음 기준 절반(A/B)으로 나눠 A로 T를 찾고 B에서 측정한 값.

## 1차 비교: 모델 종류 (같은 학습 설정)

| 모델 | Macro-F1 | 학습 시간 | CPU 추론 |
| --- | --- | --- | --- |
| TF-IDF + 로지스틱 회귀 | 0.5792 | 18초 | 0.08 ms/쌍 |
| klue/bert-base | 0.8373 | 373초 | 12.85 ms/쌍 |
| klue/roberta-base | 0.8817 | 374초 | 12.33 ms/쌍 |

- 같은 학습 설정(학습률 2e-5, 3 epoch, 배치 16)에서 RoBERTa가 BERT보다 Macro-F1이 0.044 높고,
  시간·메모리·추론 속도는 거의 같아 RoBERTa를 기반 모델로 정했다.
- 상세: classification_comparison.md, confusion_matrix.png, f1_comparison.png

## 2차 비교: RoBERTa 학습 설정 (과신 줄이기 실험)

두 사전학습 모델 모두 epoch 1 이후 validation loss가 올라가는 과신 경향을 보여,
한 번에 한 가지씩 바꾸는 추가 실험을 했다. 전체 숫자: experiment_summary.md

| 실험 | 바꾼 것 | 결과 요약 |
| --- | --- | --- |
| roberta_lr2e5_ep6 | epoch 3 → 6 | Macro-F1은 epoch 4 이후 정체, validation loss는 0.76까지 상승 (과신 심화) |
| roberta_ls01 | 라벨 스무딩 0.1 | validation loss 상승이 멈춤, T = 1.09로 보정이 거의 필요 없음 |
| roberta_ls01_ep6 | 라벨 스무딩 0.1 + 6 epoch | 6 epoch 내내 validation loss 0.40 근처 유지, Macro-F1 최고 (0.8880) |
| roberta_do02 | 드롭아웃 0.1 → 0.2 | 과신은 줄었지만 Macro-F1이 0.013 하락 (규제가 너무 셈) |
| roberta_lr1e5 | 학습률 2e-5 → 1e-5 | 과신은 줄었지만 3 epoch 안에 Macro-F1이 덜 오름 |

## 최종 판단

| 후보 | Macro-F1 | 최고와 차이 | B loss 보정 후 | B ECE 보정 후 | T |
| --- | --- | --- | --- | --- | --- |
| roberta_ls01_ep6 | 0.8880 | - | 0.4099 | 0.0176 | 1.17 |
| roberta_lr2e5_ep6 ★ | 0.8853 | 0.0027 | 0.3699 | 0.0265 | 2.77 |

- 0.005 이내 후보는 위 두 모델이며, B 절반 보정 후 loss가 낮은 roberta_lr2e5_ep6을 선정했다.
- 다른 실험은 최고와의 차이가 0.005를 넘어 후보에서 제외했다.
  (roberta_lr1e5는 B loss 보정 후가 0.3446으로 가장 낮았지만 Macro-F1 차이가 0.0108이라 제외)

## 선정 과정 기록 (시간 순)

실험을 추가할 때마다 같은 규칙을 다시 적용했다. 1등이 바뀌면 '0.005 이내' 범위도 함께 바뀐다.

| 시점 | 1등 Macro-F1 | 0.005 이내 후보 | 선정 |
| --- | --- | --- | --- |
| epoch 6 실험 후 | 0.8853 (lr2e5_ep6) | lr2e5_ep6, lr2e5 | lr2e5 (B loss 0.3537) |
| 라벨 스무딩 실험 후 | 0.8853 (lr2e5_ep6) | lr2e5_ep6, lr2e5, ls01 | lr2e5 (B loss 0.3537) |
| 모든 실험 후 (최종) | 0.8880 (ls01_ep6) | ls01_ep6, lr2e5_ep6 | **lr2e5_ep6 (B loss 0.3699)** |

- 마지막에 ls01_ep6이 1등이 되면서 lr2e5(0.8817)는 차이가 0.0063이 되어 후보에서 빠졌다.
- 중간 판단(lr2e5 + T = 2.01)은 당시 실험 범위에서는 규칙에 맞았으며, 최종 판단으로 대체했다.

## 한계

- 두 최종 후보의 차이는 매우 작고, B 절반만 보면 Macro-F1 순위가 바뀐다.
- '1등과의 차이'를 기준으로 하는 규칙이라, 새 실험이 1등을 바꾸면 이전 판단이 달라질 수 있다.
- loss 기준은 라벨 스무딩 모델에 구조적으로 불리하다. (맞힌 문제에서도 약 93%까지만 확신하도록 학습)
  확신도의 정직함(ECE)은 roberta_ls01_ep6이 가장 좋았다.
- 같은 validation으로 여러 실험을 비교해 선택 편향 가능성이 있다. 최종 성능은 test로 확인한다.
- 모든 실험은 시드 42로 1회씩 학습했다.
- roberta_ls01_ep6 학습 중 실행 확인(약 12초)이 겹쳐 학습 시간이 조금 늘었을 수 있다.
- 서비스에서는 판정을 '확정 오류'가 아닌 '검토 필요' 표시로 사용한다.

## 사후 분석 (test 평가 이후, 공식 선정에는 반영하지 않음)

- 이 분석 결과와 관계없이 공식 선정(roberta_lr2e5_ep6)과 공식 test 결과는 바꾸지 않는다.

### 목적 1: 비교 기준에 따라 선택이 바뀌는지

- Macro-F1과 보정 전 validation loss만으로 두 최종 후보를 비교하면 결과가 어떻게 달라지는지 확인
- 결과: ls01_ep6이 두 지표 모두 우세 (0.8880 / 0.4087 vs 0.8853 / 0.7592)
- 보정 후 B 절반 loss로는 lr2e5_ep6이 우세 → 비교 기준에 따라 선택이 바뀐다

### 목적 2: 라벨 스무딩 모델의 epoch을 10으로 (roberta_ls01_ep10)

- 실험 전 예상: validation loss는 0.3999(ls01_ep6의 epoch 4)보다 크게 낮아지지 않고,
  Macro-F1은 0.88 부근에서 정체할 것
- 결과
  - validation loss 최저는 epoch 2(0.3976)이며 이후 0.41~0.44에서 오르내림 → 더 떨어지지 않음
  - Macro-F1은 epoch 5부터 0.877~0.885에서 정체, 최고 0.8849(epoch 9)로 ls01_ep6(0.8880)보다 높지 않음
  - 학습 시간 1,439초로 ls01_ep6(892초)의 약 1.6배
  - 실험 전 예상과 일치. 라벨 스무딩 모델은 4~6 epoch이면 충분한 것으로 보인다
  - 학습 곡선: epoch_curves_ls_epochs.png

### 목적 3: 보정 전 validation loss 낮추기 (기준: roberta_ls01, 목표 기록 0.3803)

- 모든 실험은 loss가 가장 낮은 epoch을 저장 (--select-by loss)
- 실험 전 예상
  - roberta_ls01_lr1e5: 라벨 스무딩 0.1 + 학습률 1e-5 → 셋 중 val loss 최저(0.38 이하), Macro-F1 약 0.875
  - roberta_ls005: 라벨 스무딩 0.05 → val loss 0.38~0.42
  - roberta_ls02: 라벨 스무딩 0.2 → val loss가 0.1보다 높고, 보정 시 T < 1
- loss가 최저인 epoch을 validation으로 고르므로 val loss는 다소 유리하게 나온다. B 절반 보정 후 loss를 함께 기록한다.
- 결과 (3 epoch, loss 기준 저장)
  - roberta_ls01_lr1e5: val loss 0.3647 (epoch 2), Macro-F1 0.8750 → 목표(0.3803) 달성, 최저 기록
  - roberta_ls02: val loss 0.3903 (epoch 3, 아직 감소 중), Macro-F1 0.8844
  - roberta_ls005: val loss 0.3995 (epoch 2, epoch 3에 상승), Macro-F1 0.8669
- 보정 결과 (B 절반)
  - roberta_ls01_lr1e5: T = 1.0, B loss 0.3509 (보정 전후 동일) → 보정 없이 정직한 확률. 평균 확신도 0.887 vs 정답률 0.883
  - roberta_ls02: T = 0.87 (예상대로 T < 1) → 겸손한 모델. 보정으로 자신감을 올려 B loss 0.3751 → 0.3637
  - roberta_ls005: T = 1.23 → 조금 과장. B loss 0.3894 → 0.3780, ECE는 0.0528 → 0.0577로 오히려 증가
  - 라벨 스무딩 강도에 따라 T가 일정하게 감소: 0(2.01) → 0.05(1.22) → 0.1(1.09) → 0.2(0.85)

### 목적 4: 10 epoch으로 늘리기 (loss 기준 저장)

- 실험 전 예상
  - roberta_ls02_ep10 → val loss가 0.3903보다 낮아지지만 0.3647에는 못 미침, Macro-F1 약 0.885
  - roberta_ls01_lr1e5_ep10 → 최저 val loss는 0.3647과 비슷, Macro-F1은 0.8750보다 상승
- 결과
  - roberta_ls02_ep10: 최저 val loss 0.4161 (epoch 7), Macro-F1 0.8834 → 3 epoch(0.3903)보다 나쁨. 예상 틀림
  - roberta_ls01_lr1e5_ep10: 최저 val loss 0.4008 (epoch 2), 저장 모델 Macro-F1 0.8637 → 3 epoch(0.3647)보다 나쁨. 예상 틀림
    (Macro-F1은 학습 중 epoch 9에서 0.8861까지 올랐지만 loss 기준 저장이라 남지 않음)
  - 라벨 스무딩 0.1 실험(ls01 vs ls01_ep10)까지 포함해 세 번 모두 10 epoch의 최저 val loss가 3 epoch보다 나빴다.
- 해석: 학습률이 마지막에 0으로 줄어드는 일정이라, 3 epoch 실험은 epoch 2~3에서 마무리 효과를 받았다.
  10 epoch에서는 같은 시점의 학습률이 커서 그 효과가 없었고, 마무리 단계에는 이미 과적합이 진행됐다.
- 결론: val loss 최저는 roberta_ls01_lr1e5 (3 epoch, 0.3647). epoch 증가는 val loss 개선에 도움이 되지 않았다.

### 전체 실험에 같은 규칙 적용 (참고)

- 공식 8개 + 사후 6개, 전체 14개에 공식 선정 규칙을 그대로 적용하면 roberta_ls02가 선정된다.
  (Macro-F1 최고 0.8880에서 0.005 이내 후보 5개 중 B 절반 보정 후 loss 최저 0.3637)
- 사후 실험은 test 이후에 설계했으므로 참고로만 기록하고 공식 선정은 바꾸지 않는다.
- 상세: experiment_summary_all.md, fig_selection_rule.png

### 최종 후보 두 분류기 비교: roberta_lr2e5_ep6 vs roberta_ls01_ep6

- 목적: 공식 선정 때 마지막까지 경쟁한 두 후보(F1 1위 ls01_ep6, 보정 후 loss 1위 lr2e5_ep6)를
  test, 가상 회의록, 어려운 문장에서 비교해 선정 규칙의 결과가 다른 데이터에서도 유지되는지 확인
- 비교 항목
  1. validation (기존 결과)
  2. test 참고 평가: roberta_ls01_ep6를 test로 1회 평가 (공식 모델은 기존 결과 사용)
  3. 가상 회의록 eval 20건: 근거 찾기를 포함한 실제 서비스 조건
  4. 확인 실험 60건 (위험 40, 대조 20): 근거를 직접 준 어려운 문장 (위험한 오답 수가 주 지표)
- 공식 선정은 바꾸지 않는다. ls01_ep6의 test 결과는 test를 본 뒤의 참고 평가다.
- 결과 (results/compare_two.md)
  - validation: ls01_ep6가 Macro-F1(0.8880 vs 0.8853)과 ECE에서 앞섬
  - test: 공식 모델이 Macro-F1 0.8642 vs 0.8561, 세 라벨 F1, 보정 후 loss·ECE 모두 앞섬
  - 가상 회의록 eval 20건: 정답 10 vs 9, 위험한 오답 3 vs 3 (같은 문제에서 틀림)
  - 확인 실험 60건: 정답 55 vs 50, 위험한 오답 5 vs 6, 맞는 문장 오경보 0 vs 4
- 해석
  - validation 이후 모든 데이터에서 공식 모델이 같거나 앞섰다. F1이 근접할 때 보정 후 loss로 고른 규칙이 더 안정적인 모델을 골랐다.
  - 공식 모델의 위험한 오답 5건은 모두 주체 바뀜(같은 단어, 자리만 바뀜)이었고, 두 모델이 같은 문제에서 틀렸다.
    학습 설정이 아니라 학습 데이터의 한계로 보이며, 주체를 바꾼 모순 문장을 만들어 추가 학습하는 것이 개선 방향이다.
  - 확인 실험은 대부분 단어 하나만 바꾼 문장이라, 표현을 바꿔 쓴 가상 회의록보다 쉬웠다 (부정 표현 10/10 vs 0/3).
    점수를 실제 회의록 성능으로 해석하지 않는다.

# 2. 생성 모델(LLM)

## 생성 모델(LLM) 선정

### 결정

- 서비스 기본: 상용 gpt-6-luna (OpenAI API)
- 대체 경로: 로컬 qwen3:4b-instruct-2507-q4_K_M (Ollama) + 후처리
- 가정: 서비스 대상은 공개 회의록 (외부 API로 전송해도 되는 문서)

### 비교 방법

- 같은 입력(가상 회의록 eval 20건)과 같은 지시문으로 두 LLM을 실행. dev 5건으로 점검 후 eval은 1회만 실행
- 두 LLM은 같은 분류기 판정을 받음. 채점용 정답은 LLM에 주지 않음
- 품질: 모델 이름을 가린 블라인드 채점 (Claude가 채점, 사용자가 검토)
- 상세: results/llm_compare/eval_final_scores.md, eval_summary.md, REPORT.md

### 결과 요약

| 항목 | 로컬 (qwen3 4B) | 상용 (gpt-6-luna) |
| --- | --- | --- |
| 근거충실성 (전체) | 0.90 | 0.85 |
| 필수내용 (전체) | 0.85 | 0.60 |
| 금지내용없음 | 1.00 | 1.00 |

| 지시 위반 답변 수 | 4/20 | 0/20 |
| 판정 오류에서 재검토 표시 | 1/10 | 4/10 |
| 위험한 오답(모순→뒷받침) 3건 대응 | 반대 내용은 짚었으나 수정안 0건 | 3건 모두 재검토 표시 + 수정안 |

### 선정 근거

- 검수 서비스에서 가장 피해야 할 실패는 틀린 보고서 문장을 '뒷받침함'으로 통과시키는 것이다.
  상용 LLM은 이 경우 3건 모두 재검토를 요청하고 수정안을 제시했다.
- 상용 LLM은 지시문 규칙(단정 금지 등)을 한 번도 어기지 않았다. 로컬은 '명확한 오류' 등 단정 표현을 4번 썼다.
- 품질 점수(필수내용)는 로컬이 높았지만, 차이는 주로 분류기가 '확인 불가'로 판정한 문제에서 났다.
  이 경우는 어차피 사용자 검토 대상으로 표시되는 안전한 실패다.
- 공개 회의록 가정에서는 외부 전송이 문제되지 않고, 속도(약 0.7초)와 비용(문장당 약 0.14원) 차이는 작다.

### 대체 경로

- 상용 LLM을 쓸 수 없을 때(API 키 없음, 네트워크·API 오류) 서비스가 자동으로 로컬 LLM으로 설명한다.
- 비공개 문서는 요청 시 provider를 ollama로 지정해 로컬에서만 처리한다.
- 로컬이 설명한 답에는 금지 표현을 바꾸는 후처리를 적용한다 (nli/postprocess.py, 대체 경로 확인 실험의 결정).

### 한계

- LLM 선정 기준(위험한 오답 대응 우선)은 비교 결과를 본 뒤에 정했다. 실험 전에 정한 기준은 비교 조건과 채점 기준까지였다.
- eval은 20건이고 위험한 오답은 3건뿐이라 경향으로 해석해야 한다. (이후 확인 실험 40건에서 같은 경향을 확인)
- 채점자는 Claude 1명이며, 말투로 모델을 짐작할 수 있어 블라인드가 완전하지 않다.
- 같은 입력에도 LLM 답변은 실행마다 조금씩 달라질 수 있다. eval은 1회 실행 결과다.
- 입력은 직접 작성한 가상 회의록이라 실제 회의록에서의 성능과 다를 수 있다.

### 대체 경로 개선 확인 실험 (선정 후, 1회 실행)

- 목적: 분류기가 틀린 판정을 넘겼을 때, 대체 경로(로컬 LLM)가 상용 LLM만큼 알아채는지 확인하고 개선 방법을 비교한다.
- 데이터: data/llm_compare/stress_cases.jsonl 60건 (위험 40건: 실제로는 모순, 대조 20건: 실제로 맞음)
  - 분류기 비교(compare_two.md)에 같은 문제를 썼지만, LLM에게는 한 번도 보여주지 않았다.
- 방법: 근거 문장과 보고서 문장에 '뒷받침함' 판정(확신도 0.9)을 일부러 붙여 전달한다.
  분류기와 근거 찾기는 거치지 않는다. 지시문은 eval과 같다 (explainer.py 그대로).
- 실행 순서: 모델별로 60건을 차례로 실행한다 (문제마다 번갈아 부르면 GPU에서 4B·8B를 갈아 끼우는 시간이 응답 시간에 섞임).
- 비교 대상
  - openai: 상용 gpt-6-luna (기준)
  - local_4b: 현재 대체 경로 qwen3:4b-instruct-2507-q4_K_M
  - local_4b+후처리: 같은 답에서 금지 표현만 교체
  - local_8b: 더 큰 로컬 모델 qwen3:8b (생각 모드 모델이라 생각하는 시간이 응답 시간에 포함됨. 생각 내용은 Ollama가 빼고 최종 답만 전달)
  - local_8b+후처리: 같은 답에서 금지 표현만 교체
  - 후처리 규칙: '명확한/명백한 오류' → '원문과 다른 부분입니다', '틀린 내용' → '원문과 다른 내용', '틀렸다' → '원문과 다르다'
- 지표 (자동 채점)
  - 위험 사례: 재검토 표시, 모순 지적, 바른 내용 제시(required_any 포함 여부)
  - 대조 사례: 오경보(재검토 표시 또는 수정안 제시)
  - 전체: 지시 위반, 응답 시간
- 목표 (대체 경로가 상용만큼 동작한다고 판단하는 조건)
  - 위험 사례의 재검토 표시, 바른 내용 제시가 각각 openai와 4건 이내 차이 (위험 40건의 10%)
  - 지시 위반 0건
  - 대조 사례 오경보가 openai 이하
- 결정 규칙
  - 목표를 달성한 로컬 구성 중 응답 시간이 가장 짧은 것을 대체 경로로 채택한다.
  - 달성한 구성이 없으면 대체 경로는 local_4b+후처리로 두고, 미달 항목을 한계로 기록한다.
- 보조 분석: 주체 바뀜 10건은 분류기가 실제로 틀린 유형(공식 모델 위험한 오답 5건)이라 따로 본다.
- 상용 LLM을 서비스 기본으로 한 선정은 바꾸지 않는다.

- 결과 (results/llm_compare/stress_compare_summary.md)

  - 모순 지적: 세 모델 모두 40/40 (로컬도 차이는 알아채지만 지시된 경고 표시를 덜 붙임)
